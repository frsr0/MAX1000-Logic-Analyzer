# MCP4725 DAC test and signal generator

The **MIL → MCP4725 DAC and signal generator** card sends I²C writes to a wired
MCP4725 module and checks VOUT on a MAX1000 analogue input. It also sends short
stepped waveforms and saves a scope session. The mock device runs the same UI
workflow with synthetic voltages.

## Connect the board

| MCP4725 module | Verified MAX1000 connection |
|---|---|
| VCC | 3.3 V |
| GND | Common ground |
| SDA | D4, J1/13 (MKR pin index 4) |
| SCL | D3, J1/12 (MKR pin index 3) |
| VOUT | AIN4, J1/6 (ADC channel 3) |

This is the route used in the [final physical test record](../evidence/mcp4725-fast-timing-clean/README.md).
The card can select any two **different** external digital pins from D0–D14
and PIO_01–PIO_08 (23 choices for each line), any of AIN3, AIN1, AIN4, or
AIN6, and I²C address `0x60`–`0x67`. The software routing test exercises all
506 ordered pairs of different digital pins; the attached DAC was physically
verified only on D4/D3. Match the UI selections to the actual wires.

Use a 3.3 V supply and pull SDA and SCL up to 3.3 V; check whether the module
already provides pull-ups. Keep VOUT within the analogue input's 0–3.3 V
range. A board showing approximately 1.65 V at VOUT may simply be holding a
midscale code; run the I²C test to confirm communication.

## Use the MIL card

1. Connect **MAX1000 OLS Logic Analyzer** on **Device** and acquire the control
   lock. Open **MIL**. Stop an active capture or live accelerometer run first.
2. Select the actual address, SDA, SCL, and VOUT input. The verified setup uses
   `0x60`, D4, D3, and AIN4.
3. Choose **Run three-point test** to write codes 0, 2048, and 4095, or **Set
   code and measure** for one code. The result shows expected and measured
   voltage, error, and the three physical I²C ACK bits for each write. The
   default voltage tolerance is ±0.20 V.
4. Select sine, triangle, sawtooth, or square, then set frequency, steps,
   cycles, and voltage range. Choose **Run waveform and save trace**, then
   **Open scope trace** to inspect the saved session.

Waveforms are limited to 0.25–2 Hz, 8–24 DAC writes per cycle, 1–3 cycles,
at most 20 writes/s, and at most 12 seconds of requested output. The output
holds its last code afterward. The card writes the volatile DAC register; it
does not write the module's EEPROM. To leave the output near midscale, set code
2048 after the waveform.

## What PASS and the saved trace mean

For a hardware waveform, the app first writes every distinct DAC code and
measures its voltage through the chosen analogue input. During the scheduled
pass it sends each code through the FPGA I²C receive FIFO and checks the slave
ACKs without pausing for an ADC/SDRAM capture. A PASS requires voltage errors
within tolerance, all ACKs, and an actual write rate within ±20% of the
requested rate.

The saved scope staircase **replays the preflight measured levels** at the
host-measured write cadence. It is not a simultaneous analogue recording of
the timed pass. The rate comes from monotonic host write timestamps, not an
independent oscilloscope. The session notes and `trace_source` field identify
this provenance. Mock sessions use synthetic levels and are marked SIMULATED.

On the final seed-7 image, verify-only passed at 17:46:54 before the physical
retests. The wired MCP4725 passed 0.5 Hz/8-step sine at 0.5000 Hz, 0.25 Hz/24-step
sine at 0.2493 Hz, 2 Hz/8-step output at 2.0023 Hz, and 2 Hz/10-step square at
2.0548 Hz. All passed voltage, timing, and ACK checks. A wrong address (`0x61`
on the verified `0x60` board) produced NACK and FAIL as expected. See the
[seven screenshots and response JSON](../evidence/mcp4725-fast-timing-clean/README.md).
The image passed its post-fit timing gate; see the
[final image evidence](../evidence/mcp4725-fast-timing-clean/README.md) for POF
identity, timing margins, and related board checks.

## If a test fails

- **NACK:** Check the selected address, the SDA/SCL labels and header positions,
  pull-ups, power, and common ground. An unwired or wrong SCL pin was observed
  to fail the physical test.
- **Voltage error with ACK:** Check VOUT-to-AIN wiring, selected ADC input,
  3.3 V supply, ground, and voltage tolerance.
- **Timing failure:** Reduce `frequency × steps per cycle`, or inspect the
  reported actual rate. The preflight voltage measurements happen before the
  timed pass and are excluded from that rate.
